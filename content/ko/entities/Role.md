## 예시 {#example}

```json
{
	"id": "3",
	"name": "Owner",
	"color": "#ff3838",
	"permissions": "1048575",
	"highlighted": true,
    "collection_limit": 10
}
```

## 속성 {#attributes}

### `id` {#id}

**설명:** 데이터베이스의 Role ID입니다.\
**유형:** 문자열\
**버전 이력:**\
4.0.0 - 추가

### `name` {#name}

**설명:** 역할 이름입니다.\
**유형:** 문자열\
**버전 이력:**\
4.0.0 - 추가

### `color` {#color}

**설명:** 이 역할에 할당된 16진수 색상 코드입니다. 코드가 할당되지 않으면 빈 문자열입니다.\
**유형:** 문자열\
**버전 이력:**\
4.0.0 - 추가

### `permissions` {#permissions}

**설명:** 역할에 부여된 모든 권한의 합을 나타내는 비트마스크입니다. 십진수로 표현한 큰 정수일 수 있습니다. 특별한 권한이 없으면 `'0'`으로 표시합니다.\
**유형:** 문자열\
**버전 이력:**\
4.0.0 - 추가

### `highlighted` {#highlighted}

**설명:** 역할을 사용자 프로필에 배지로 공개할지 나타냅니다.\
**유형:** 불리언\
**버전 이력:**\
4.0.0 - 추가

### `collection_limit` {#collection_limit}

**설명:** 이 역할을 가진 사용자가 생성할 수 있는 최대 컬렉션 수입니다.\
**유형:** 정수\
**버전 이력:**\
4.6.0 - 추가

## 권한 플래그 {#permission-flags}

특정 역할의 권한을 확인하려면 `permissions` 속성을 이진수로 변환하고 최하위 비트부터 비교합니다. 편의를 위해(용어가 너무 길어지는 것을 막기 위해) 아래에서는 권한을 16진수 값으로 표시합니다.

0x1
: **관리자**. 이 권한이 있는 사용자는 모든 권한 검사를 우회합니다.

0x2
: **Devops**. 사용자가 Sidekiq와 PgHero 대시보드에 접근할 수 있습니다.

0x4
: **감사 로그 보기**. 사용자가 관리자 작업 이력을 볼 수 있습니다.

0x8
: **대시보드 보기**. 사용자가 대시보드와 여러 지표에 접근할 수 있습니다.

0x10
: **신고 관리**. 사용자가 신고를 검토하고 관련 중재 조치를 수행할 수 있습니다.

0x20
: **연합 관리**. 사용자가 다른 도메인과의 연합을 차단하거나 허용하고 전달 가능 여부를 제어할 수 있습니다.

0x40
: **설정 관리**. 사용자가 사이트 설정을 변경할 수 있습니다.

0x80
: **차단 관리**. 사용자가 이메일 제공자와 IP 주소를 차단할 수 있습니다.

0x100
: **분류 관리**. 사용자가 유행 콘텐츠를 검토하고 해시태그 설정을 갱신할 수 있습니다.

0x200
: **이의 제기 관리**. 사용자가 중재 조치에 대한 이의 제기를 검토할 수 있습니다.

0x400
: **사용자 관리**. 사용자가 다른 사용자의 상세 정보를 보고 중재 조치를 수행할 수 있습니다.

0x800
: **초대 관리**. 사용자가 초대 링크를 조회하고 비활성화할 수 있습니다.

0x1000
: **규칙 관리**. 사용자가 서버 규칙을 변경할 수 있습니다.

0x2000
: **공지 관리**. 사용자가 서버 공지를 관리할 수 있습니다.

0x4000
: **사용자 지정 이모지 관리**. 사용자가 서버의 사용자 지정 이모지를 관리할 수 있습니다.

0x8000
: **웹훅 관리**. 사용자가 관리 이벤트의 웹훅을 설정할 수 있습니다.

0x10000
: **사용자 초대**. 사용자가 새 사용자를 서버에 초대할 수 있습니다.

0x20000
: **역할 관리**. 사용자가 자신의 역할보다 낮은 역할을 관리하고 할당할 수 있습니다.

0x40000
: **사용자 접근 관리**. 사용자가 다른 사용자의 2단계 인증을 비활성화하고 이메일 주소를 변경하며 비밀번호를 재설정할 수 있습니다.

0x80000
: **사용자 데이터 삭제**. 사용자가 다른 사용자의 데이터를 지체 없이 삭제할 수 있습니다.

0x100000
: **실시간 및 주제 피드 보기**. 공개 전체 스트림, 해시태그 및 링크 피드가 비활성화되어 있어도 사용자가 이를 볼 수 있습니다.
