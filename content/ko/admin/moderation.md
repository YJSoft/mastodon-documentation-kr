## 공지 {#announcements}

사용자에게 서버 관련 행사나 안내를 전달하려면 관리 및 중재 영역의 “공지” 기능을 사용할 수 있습니다.

공지를 보내려면 “관리 -> 공지”로 이동하고 “새 공지”를 선택합니다. 양식에 최소한 공지 본문을 입력하고 필요하면 관련 날짜 정보도 입력합니다. 공지는 즉시 게시하거나 나중에 게시하도록 예약할 수 있습니다. 게시되면 앱 안의 사용자 공지 피드에 나타납니다.

공지에 관해 이메일도 보내려면 공지 목록에서 “사용자에게 알림”을 선택하고 미리 보기를 확인한 다음 “보내기”를 클릭합니다. 먼저 자신에게 미리 보기 이메일을 보낼 수도 있습니다. 사용자가 이 이메일을 수신 거부할 수 없으므로 중요한 안내에만 사용합니다.

## 개별 사용자 중재 {#individual-moderation}

마스토돈의 중재는 항상 로컬, 즉 해당 서버에서 보이는 모습에 적용됩니다. 한 서버의 관리자나 중재자는 다른 서버의 사용자에게 영향을 줄 수 없으며 자기 서버의 로컬 사본에만 영향을 줄 수 있습니다.

v3.5.0부터 모든 기본 사용자 중재 결정은 해당 사용자에게 이메일로 통지됩니다. 사용자는 이의 제기 페이지에서 결정 후 20일 이내에 한 번 이의를 제기할 수 있습니다. 중재자는 이의를 승인하거나 거절할 수 있습니다.

### 민감함 {#sensitive-user}

계정을 민감함으로 표시하면 해당 사용자가 게시하는 모든 미디어가 자동으로 [민감함으로 표시됩니다](https://docs.joinmastodon.org/user/posting/#cw).

### 동결 {#freeze-user}

마스토돈 계정을 동결할 수 있습니다. 사용자는 계정으로 아무 작업도 할 수 없지만 모든 콘텐츠는 그대로 남습니다. 이 제한은 되돌릴 수 있으며 언제든지 동결을 해제할 수 있습니다. 자신의 서버에 있는 로컬 사용자에게만 적용할 수 있습니다.

사용자 계정을 동결하면 **계정 설정** 페이지로 이동하며 다음 메시지가 표시됩니다.

> 더 이상 계정에 로그인하거나 다른 방식으로 사용할 수 없지만 프로필과 다른 데이터는 그대로 유지됩니다.

계정 동결을 해제하면 정상 기능이 복구됩니다.

### 제한 {#limit-user}

이전에는 “숨김”이라고 불렀습니다. 제한된 계정은 해당 서버의 팔로워를 제외한 모든 사용자에게 숨겨집니다. 콘텐츠는 그대로 남아 검색, 멘션, 팔로우로 찾을 수 있지만 공개적으로는 보이지 않습니다. 제한된 계정의 활동 알림은 계정별 알림 환경설정에 따라 처리됩니다. 제한된 계정의 기본값은 “필터링”입니다.

제한된 계정이 해당 서버의 사용자를 팔로우하려 하면 팔로우 요청으로 전환됩니다.

현재 제한은 연합에 영향을 주지 않습니다. 로컬에서 제한된 계정이 다른 서버에서도 자동으로 제한되는 것은 *아닙니다*. 계정 제한은 되돌릴 수 있습니다.

### 정지 {#suspend-user}

마스토돈에서 정지는 계정이 사실상 삭제됨을 뜻합니다. 더 이상 검색에 나타나지 않고 프로필 페이지도 없어지며 모든 게시물, 업로드, 팔로워 및 기타 데이터가 공개적으로 제거됩니다. 다만 정지 후 30일 동안은 관리자 백엔드에서 모든 데이터를 볼 수 있습니다. 사용자가 서버 관리자와 협의하여 문제를 해결하고 계정을 복구할 기회를 주기 위한 것입니다.

30일 이내에 계정이 복구되면 프로필과 모든 게시물을 다시 공개적으로 볼 수 있습니다. 다만 정지 시 서버 간 팔로우 관계가 끊어질 수 있으며 계정을 복구해도 자동으로 복구되지 않습니다. 30일이 지나면 사용자의 **모든** 데이터가 서버에서 영구 삭제됩니다. 관리자는 이 30일 안에도 언제든 계정 데이터를 즉시 삭제할 수 있습니다.

30일이 지나거나 관리자가 강제 삭제하여 데이터가 삭제된 후에도 계정 정지는 해제할 수 있습니다. 하지만 계정에는 연결된 데이터(게시물, 프로필 정보, 아바타, 헤더 이미지)가 없습니다.

원격 계정을 정지하면 모든 로컬 계정의 팔로우가 해제됩니다. 30일 이내라도 원격 계정 정지를 해제할 때 이 관계는 복구되지 않습니다.

기본적으로 서버에서 정지된 사용자도 해당 서버의 게시물을 계속 볼 수 있습니다. 이를 변경하려면 관리자가 `AUTHORIZED_FETCH` 환경 변수를 설정할 수 있습니다. [환경 설정 문서](../config/)를 확인합니다.

## 웹사이트 전체 중재 {#server-wide-moderation}

문제가 있는 서버의 많은 사용자를 개별 중재하기는 힘들 수 있으므로, 여러 심각도 수준을 제공하는 **도메인 차단**으로 특정 서버의 모든 사용자를 선제적으로 중재할 수 있습니다. **환경설정** &gt; **중재** &gt; **연합**으로 이동하고 “새 도메인 차단 추가”를 클릭하여 서버를 차단합니다.

### 미디어 거부 {#reject-media}

이 옵션을 활성화하면 해당 서버의 파일을 로컬에서 처리하지 않습니다. 아바타, 헤더, 이모지, 미디어 첨부 파일이 모두 포함됩니다.

### 제한 {#limit-server}

해당 서버의 과거 및 미래의 모든 계정을 [제한](#limit-user)하는 것과 같습니다. 이전에는 “숨김”이라고 불렀습니다. 특히 팔로우되는 계정이 팔로워 승인을 요구하지 않아도 제한된 서버에서 오는 모든 팔로우가 자동으로 팔로우 요청이 됩니다.

### 정지 {#suspend-server}

해당 서버의 과거 및 미래의 모든 계정을 [정지](#suspend-user)하는 것과 같습니다. 사용자명 외에는 해당 서버의 어떤 콘텐츠도 로컬에 저장하지 않습니다.

서버를 정지하면 로컬 계정과 정지된 서버의 계정 사이의 기존 팔로우 관계가 모두 제거됩니다. 나중에 원격 서버 정지를 해제해도 복구되지 않습니다.

### 차단 목록 {#blocklist}

“차단 목록”은 다른 관리자가 문제가 있다고 판단한 서버 목록이 담긴 파일이며, 문제 콘텐츠를 설명하는 주석이 포함될 수 있습니다. 차단 목록을 가져와 해당 서버가 자신의 마스토돈 서버와 상호작용하지 못하도록 차단할 수 있습니다.

차단 목록을 다운로드한 다음 **환경설정** &gt; **중재** &gt; **연합**으로 이동하여 “가져오기”를 클릭합니다. 차단 목록의 `.csv` 파일을 선택하고 “업로드”를 클릭합니다. 마스토돈은 목록을 검토할 기회를 제공하며 원한다면 개별 서버의 선택을 해제할 수 있습니다. 마치면 “가져오기”를 클릭하여 선택한 서버를 차단합니다.

“내보내기”로 서버의 차단 목록을 백업하거나 다른 관리자와 공유할 수도 있습니다.

기본적으로 정지된 서버의 사용자는 정지를 수행한 서버의 게시물을 계속 볼 수 있습니다. 이를 변경하려면 관리자가 `AUTHORIZED_FETCH` 환경 변수를 설정할 수 있습니다. [환경 설정 문서](../config/)를 확인합니다.

## 스팸 방지 조치 {#spam-fighting-measures}

마스토돈에는 스팸을 방지하는 몇 가지 기본 조치가 있습니다.

* 가입 시 이메일 주소 확인이 필요합니다.
* IP별로 가입 요청 빈도가 제한됩니다.

하지만 집요한 스팸 발송자는 이를 통과합니다. 추가로 사용할 수 있는 조치는 **이메일 도메인 차단 목록**입니다. 가입 시 마스토돈은 제공된 이메일 주소의 A 또는 MX 레코드, 즉 이메일 서버의 IP 주소를 확인하고 동적으로 저장된 차단 목록과 대조합니다.

### 이메일 서버로 차단 {#blocking-by-e-mail-server}

스팸 발송자는 종종 서로 다른 이메일 도메인을 사용하여 개별 차단이 어려운 여러 이메일 서버를 사용하는 것처럼 보이게 합니다. 하지만 모든 도메인이 하나의 이메일 서버 IP로 연결되는 경우가 있습니다. 동시에 많은 스팸 계정이 가입한다면 온라인 DNS 조회 도구나 Linux `dig` 유틸리티로 확인할 수 있습니다. 예를 들어 `dig example.com`은 해당 도메인의 모든 DNS A 레코드를 반환합니다. 모든 도메인의 IP가 같다면 이메일 도메인 차단 목록에 추가할 수 있습니다.

### IP로 차단 {#blocking-by-ip}

IP 차단은 완벽한 전략이 아닙니다. IP는 때때로
여러 사람이 공유하며 사용자가 바뀌기도 합니다. 실수로
넓은 IP 범위를 차단하여 정상 접근을 막을 수도 있습니다. 어느 방법이든
주의해서 사용합니다.

#### IP 차단 {#ip-blocks}

중재 인터페이스의 “IP 규칙” 페이지에서 IP 주소
기반 차단을 만들 수 있습니다. 특정 IPv4 또는 IPv6 주소를 차단하거나
[CIDR] 구문으로 전체 범위를 차단할 수 있습니다. 페이지의 안내에 따라
차단 기간과 애플리케이션 내 차단의 심각도를
설정할 수 있습니다.

[CIDR]: https://en.wikipedia.org/wiki/Classless_Inter-Domain_Routing

#### 방화벽 규칙 {#firewall-rules}

Linux에서는 방화벽으로 IP 주소에 따라 방문자를 차단할 수도 있습니다.
다음은 `iptables`와 `ipset`을 사용하는 예제입니다.

```bash
# Install ipset
sudo apt install ipset
# Create blacklist named "spambots"
sudo ipset create spambots nethash
# Add 1.2.3.4 to the blacklist
sudo ipset add spambots 1.2.3.4
# Add firewall rule based on the blacklist
sudo iptables -I INPUT 1 -m set --match-set spambots src -j DROP
```

자신의 컴퓨터에 접근하지 못하게 되지 않도록 주의합니다.

### 중재 수준 이벤트의 웹훅 {#report-events-webhook}

중재 API를 통한 자동화를 지원할 수 있습니다. 또한
