{{< hint style="info" >}}
마스토돈 새 버전이 출시되면 [GitHub 릴리스 페이지](https://github.com/mastodon/mastodon/releases)에 표시됩니다. `main` 브랜치의 미출시 코드를 실행할 수는 있지만 권장하지 않습니다.
{{< /hint >}}

### 버전 체계 {#versioning}

일반적으로 마스토돈 버전 체계는 [SemVer](https://semver.org)의 취지를 따릅니다.

- 주 버전(4.x에서 5.x)은 애플리케이션 동작이나 API 응답에 하위 호환성이 없는 변경(“호환성을 깨는 변경”)을 도입하거나 기본 시스템 요구 사항을 크게 바꿀 수 있습니다.
- 부 버전(4.1.x에서 4.2.x)은 하위 호환성을 유지하면서 기능을 추가하고 의존성을 소폭 변경할 수 있습니다.
- 패치 버전(4.2.1에서 4.2.2)은 하위 호환성을 유지하는 버그 수정이나 작은 개선을 추가합니다.

모든 릴리스에는 릴리스 노트와 변경 내역이 함께 제공되며, 해당 릴리스의 변경 사항을 확실히 확인하는 가장 좋은 방법은 이를 읽는 것입니다.

### 자동 업데이트 확인 {#automated_checks}

v4.2.0부터 마스토돈은 사용 가능한 업데이트를 자동으로 확인하고 서버에서 `DevOps` 권한을 가진 사용자에게 알립니다.

이를 위해 백그라운드에서 30분마다 `https://api.joinmastodon.org/update-check?version=<current_version>`을 가져옵니다. `current_version`에는 빌드 메타데이터, 즉 버전 문자열에 +가 있다면 첫 번째 `+` 이후의 모든 내용을 포함하지 않습니다. 예를 들어 버전이 `4.3.0-beta2+my-fork`이면 `https://api.joinmastodon.org/update-check?version=4.3.0-beta2`를 조회합니다.

`UPDATE_CHECK_URL` 환경 변수로 조회할 URL을 바꿀 수 있습니다. 이 변수를 빈 문자열로 설정하면 이 동작을 완전히 비활성화할 수도 있습니다. 다만 마스토돈은 때때로 제때 적용해야 하는 중요한 보안 업데이트를 출시하므로, 다른 방식으로 마스토돈 업데이트를 확인하고 있지 않다면 비활성화하지 않을 것을 강력히 권장합니다.

### 업그레이드 단계 {#upgrade-steps}

마스토돈 릴리스는 git 태그에 대응합니다. 업그레이드하기 전에 [GitHub 릴리스 페이지](https://github.com/mastodon/mastodon/releases)에서 원하는 릴리스를 찾습니다. 이 페이지에는 모든 변경 사항을 설명하는 **변경 내역**과 **구체적인 업그레이드 지침**이 있습니다.

먼저 `mastodon` 사용자로 전환합니다.

```bash
su - mastodon
```

그런 다음 마스토돈 루트 디렉터리로 이동합니다.

```bash
cd /home/mastodon/live
```

버전 이름이 `v3.1.2`라고 가정하고 릴리스 코드를 다운로드합니다.

```bash
git fetch --tags
git checkout v3.1.2
```

이제 GitHub의 해당 버전 릴리스 노트에 있는 업그레이드 지침을 실행합니다. 릴리스마다 필요한 지침이 다르므로 이 페이지에는 지침을 넣지 않습니다.

{{< hint style="info" >}}
오래된 버전에서 업그레이드할 때 모든 패치 버전(위 참고)을 하나씩 배포하지 않아도 안전합니다. 각 버전을 개별 배포할 필요는 없습니다. 다만 각 부 버전 계열에서는 최소 한 릴리스를 배포해야 합니다. 특히 각 릴리스 또는 여러 릴리스의 지침을 빠뜨리지 않아야 합니다. 지침 대부분은 겹치므로 모든 지침을 최소 한 번씩 실행했는지 확인하면 됩니다.
{{< /hint >}}

릴리스 노트의 지침을 실행한 다음 root로 돌아갑니다.

```bash
exit
```

**백그라운드 작업자**를 재시작합니다.

```bash
systemctl restart mastodon-sidekiq
```

그리고 **웹 프로세스**를 다시 불러옵니다.

```bash
systemctl reload mastodon-web
```

{{< hint style="info" >}}
`reload`는 “단계적 재시작”이라고도 하는 중단 없는 재시작입니다. 따라서 마스토돈 업그레이드는 보통 사용자에게 예정된 중단을 미리 알릴 필요가 없습니다. 드물게 대신 `restart`를 사용할 수 있지만 사용자가 느끼는 짧은 서비스 중단이 발생합니다.
{{< /hint >}}

**스트리밍 API** 서버도 업데이트되므로 재시작해야 합니다. 그러면 연결된 모든 클라이언트가 끊어져 서버 부하가 증가할 수 있습니다.

```bash
systemctl restart mastodon-streaming
```

{{< hint style="danger" >}}
스트리밍 API를 재시작하면 연결이 끊긴 클라이언트가 재연결하거나 대신 REST API를 폴링하여 서버 부하가 증가하므로 가능하면 피합니다.
{{< /hint >}}

{{< hint style="success" >}}
**완료되었습니다!** 이제 새 버전의 마스토돈을 실행하고 있습니다.
{{< /hint >}}
